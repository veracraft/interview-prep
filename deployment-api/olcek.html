Follow-up soruları

Önce soruyu oku, 20 saniyede kendi cevabını sesli söyle, sonra aç.

1. How do you handle many clusters or regions?

Ana fikir: Argo CD ApplicationSet ile her cluster'a aynı uygulama; bölge bölge ilerle (önce bir bölgenin dosyası, sağlıklıysa diğeri).

Argo CD's ApplicationSet gives every cluster the same app. I'd roll out region by region: the worker commits the new digest for one region first, and only after that region is healthy for the next one, so a bad version only hits one region.
2. How do you know a canary is healthy?

Ana fikir: Argo Rollouts analizi: canary'yi aynı anda çalışan eski sürümle karşılaştır; yeterli trafik yoksa bekle.

Argo Rollouts runs an analysis after each step that compares the canary with the stable pods at the same time, error rate and p99, instead of a fixed threshold, because traffic changes during the day. If there isn't enough traffic, the analysis is inconclusive and we hold.
3. Deploys grow from 500 to 50,000 a day. What changes?

Ana fikir: Önce ölç: Git'e yazma hızı ve Argo CD darboğaz olur (repo bölme, Argo CD sharding); olay dinleyenler artarsa pending_events + Kafka.

First I'd measure. Postgres as a queue is fine for much more; the first limits are Git and Argo CD: many commits to one repo conflict, and one Argo CD instance gets slow with thousands of apps. So I'd split config repos per team or domain and shard Argo CD. If other systems want deploy events, I'd add a pending_events table and Kafka.
4. Why not let teams just merge a PR to the config repo?

Ana fikir: Küçük ekipte olur; ama politika (sahiplik, imza, onay) ve durum dağınık kalır. API bunları tek yerde toplar.

For a small team that works. But policy like ownership, signed images and prod approval ends up spread over CODEOWNERS and branch rules, and CI has to read Git, Argo CD and Rollouts to know the status. The API keeps policy and status in one place, and still uses Git underneath.
5. Why REST and not gRPC?

Ana fikir: CI ve CLI'dan kolay çağrılır, gateway'den geçer, insan okuyabilir; yüksek hacimli iç trafik yok.

Callers are CI pipelines and a CLI, so plain HTTP and JSON is the easiest to use, debug and put behind our gateway. There's no high-volume service-to-service traffic here where gRPC would really pay off.
