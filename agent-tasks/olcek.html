Follow-up soruları

Önce soruyu oku, 20 saniyede kendi cevabını sesli söyle, sonra aç. Genel sorular: Genel takip soruları.

1. One customer suddenly sends thousands of tasks. What happens?

Ana fikir: LLM gateway'de tenant bütçesi; yeni task'lar 429 + Retry-After; worker'larda tenant başına eşzamanlılık sınırı.

All model calls go through the LLM gateway, which keeps a token budget per tenant. When a tenant is over, new tasks get 429 with Retry-After, and a per-tenant concurrency limit on workers keeps other customers unaffected.
2. The model provider is down or returns 429.

Ana fikir: Backoff, circuit breaker, aynı bölgede yedek model; olmazsa bekleyen task'lar kuyrukta kalır.

The gateway backs off, opens a circuit breaker if errors continue, and falls back to another model only if it's allowed for the customer's region. If nothing works, tasks wait in the queue instead of failing.
3. How many open streams can one API pod hold?

Ana fikir: SSE bağlantısı ucuz ama sayılı; API'yi açık bağlantı sayısına göre ölçekle, CPU'ya göre değil; heartbeat.

An SSE connection is cheap but not free, so I scale the API on open connections, not CPU, and plan a few thousand per pod. A heartbeat every 15 seconds keeps the gateway from closing idle streams.
4. A task waits hours for approval.

Ana fikir: Worker'ı tutma: task requires_action'a geçer, lease bırakılır; onay gelince tekrar kuyruğa; süre dolunca expired.

The worker doesn't wait. The task moves to requires_action and releases its lease; the approval puts it back on the queue. If nobody answers in, say, 24 hours, it expires.
5. How do you control cost?

Ana fikir: Task başına token × task sayısı; tenant bütçesi; bağlam boyutunu sınırla; basit adımlar için ucuz model; tenant başına maliyet paneli.

Cost is tokens per task times tasks per day, and the model is the biggest cost, not CPU. I control it with per-tenant budgets, limits on context size, cheaper models for simple steps, and cost per tenant on a dashboard.
6. What about multiple regions and data residency?

Ana fikir: Tenant bir bölgeye bağlı: veritabanı, stream ve model uç noktası aynı bölgede; yedek model sadece izinli bölgede.

Each tenant is pinned to a region: database, stream and model endpoint all live there, and fallback only uses models allowed in that region.
