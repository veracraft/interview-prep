Agent Tasks · 2. API sözleşmesi

Playbook 2/5 · API sözleşmesi. Ne yaparsın: endpoint'ler → bir tam request/response → durumlar → hatalar. Idempotency ve yetkiyi burada söyle. Gösterdiğin: istemcinin servisi nasıl kullanacağını.

Önce kağıda kendin yaz, sonra butonla karşılaştır.

Endpoint'e ya da hata koduna tıkla: altında istek ve cevap açılır. ↗ işaretli hücreye tıkla: ilgili karar açılır.

Kaynaklar: conversation · message · task (uzun süren iş) · task event (sıra numaralı) · tool call

Akış: istemci gönderir → API kaydeder (tek transaction) → 202 döner → istemci akışı açar ya da Location'ı sorar. Aşağıda aynı istek satır satır.

İstekNe demek, neden?
POST /v1/conversations/cv_1/taskscv_1 konuşmasında yeni bir task başlat. Task konuşmanın altında yaşar; konuşma başına tek aktif task kuralı buradan gelir.
Authorization: Bearer <JWT>Kim olduğun: tenant ve kullanıcı token'dan. Tool'lar da bu kullanıcının yetkisiyle çalışacak. Token'dan nasıl? →
Idempotency-Key: 8a0d…Slack ya da mobil ağ hatasında aynı isteği tekrar gönderir; aynı anahtar aynı task'ı döndürür, ikinci cevap ve ikinci maliyet olmaz.
{ "input": "Q3'te churn neden arttı? …" }Kullanıcının mesajı. Task ile aynı transaction'da konuşma geçmişine yazılır.
CevapNe demek, neden?
202 Accepted"Aldım ve kaydettim; task arka planda çalışacak." Task saniyeler ile dakikalar sürer, HTTP isteği bekletilmez.
Location: /v1/tasks/task_7d2Durumu nereden soracağın. Canlı izlemek için /v1/tasks/task_7d2/events.
{ "id": "task_7d2", "status": "queued" }Task'ın kimliği ve ilk durumu.

Web istemcisi aynı isteği Accept: text/event-stream ile atarsa cevap doğrudan 200 + canlı akış olur; ayrı bir istek gerekmez.

queued → running ⇄ requires_action → completed | failed | cancelled

KuralKarar
TekrarAynı Idempotency-Key → aynı task döner.
EşzamanlıKonuşma başına tek aktif task.
YetkiKullanıcı sadece kendi konuşmasını görür; onayı task'ın sahibi verir; akış okunmadan önce sahiplik kontrolü.
İptal:cancel idempotent; zaten çalışmış tool çağrıları geri alınmaz.
Tool tekrarıYazan tool en fazla bir kez: side_effect_key.
Creating a task returns 202 with a task id, and the client can follow it live over SSE. Every event has a sequence number, so a client that reconnects just sends Last-Event-ID.
