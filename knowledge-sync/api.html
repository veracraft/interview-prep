Knowledge Sync · 2. API sözleşmesi

Playbook 2/5 · API sözleşmesi. Ne yaparsın: endpoint'ler → bir tam request/response → durumlar → hatalar. Idempotency ve yetkiyi burada söyle. Gösterdiğin: istemcinin servisi nasıl kullanacağını.

Önce kağıda kendin yaz, sonra butonla karşılaştır.

Endpoint'e ya da hata koduna tıkla: altında istek ve cevap açılır. ↗ işaretli hücreye tıkla: ilgili karar açılır.

Kaynaklar: source (bağlı kaynak) · sync job (uzun süren iş) · document · search (aksiyon)

Akış: istemci gönderir → API kaydeder (tek transaction) → 202 döner → istemci Location'daki adresi sorar. Aşağıda aynı istek satır satır.

İstekNe demek, neden?
POST /v1/sources/src_8f2/syncssrc_8f2 kaynağı için yeni bir sync oluştur. Sync, kaynağın altında yaşayan bir alt kaynak; o yüzden yol /sources/{id}/syncs.
Authorization: Bearer <JWT>Kim olduğun. Token'da tenant ve kullanıcı var. Tenant'ı body'den asla almayız; böylece kimse başka müşteri adına iş başlatamaz. Token'dan nasıl? →
Idempotency-Key: 4f1c…İstemcinin ürettiği tek seferlik anahtar. Ağ koparsa aynı anahtarla tekrar gönderir; ikinci bir sync açılmaz, ilk cevap döner.
{ "mode": "incremental" }Ne yapılacağı: sadece değişenleri çek. full her şeyi baştan tarar.
CevapNe demek, neden?
202 Accepted"Aldım ve kaydettim, ama iş henüz bitmedi." 200 değil, çünkü sync daha yapılmadı. Bu kod dönmeden önce iş veritabanına yazılmış olmalı.
Location: /v1/syncs/sync_123Durumu nereden soracağın. İstemci bu adrese GET atar.
{ "id": "sync_123", "status": "queued" }İşin kimliği ve ilk durumu: sırada bekliyor.
queued → running → succeeded | failed | cancelled

GET /v1/syncs/sync_123 → 200
{ "id": "sync_123", "status": "running",
  "progress": { "processed": 1200, "failed": 3 } }

{ "id": "sync_123", "status": "failed",
  "error": { "code": "SOURCE_AUTH_EXPIRED",
             "message": "Reconnect Google Drive" } }

Tek hata formatı: her hata aynı şekilde döner: makine için sabit code, insan için message, loglarla eşleşen request_id, gerekirse details.

KuralKarar
TekrarAynı Idempotency-Key → aynı sync döner.
EşzamanlıKaynak başına tek aktif sync; zaten çalışıyorsa mevcut sync 200 ile döner.
YetkiBaşlatma: tenant admin. Görme: admin + viewer. Başka tenant → 404.
SilmeDELETE → 202: yeni sync reddedilir, çalışan durur, aramadan hemen çıkar, veri arka planda silinir.
Every POST takes an Idempotency-Key, and the tenant comes from the token, never from the body. I'll come back to how that works.
