Mülakat hazırlığı: API ve mimari

Bir AI şirketinde Infrastructure Engineer pozisyonunun API Development & Solutions Design turu için Türkçe çalışma notları. Üç sistem var; her biri mülakat playbook'unun sırasıyla ilerliyor.

Nasıl kullanılır? Üstten bir sistem seç. Alt menüdeki 1 → 5 sırası mülakattaki sırayla aynı; her sayfanın sonunda "sonraki adım" linki var. Diyagramdaki kutulara ve tablo satırlarına tıklayınca ilgili açıklama açılır.
Sistem 1 · yazma ağırlıklı

Knowledge Sync

Şirket dokümanlarını ve izinlerini Drive, Slack gibi kaynaklardan içeri alır, izinlere göre aranabilir yapar. Zor kısım: izin doğruluğu, kaynak kotaları, tenant'lar arası adalet.
Sistem 2 · gecikmeye duyarlı

Agent Tasks

Kullanıcının asistana verdiği görevi çalıştırır, cevabı canlı akıtır, tool çağırır. Zor kısım: uzun iş, kopmaya dayanıklılık, tool'ların iki kez çalışmaması, LLM maliyeti.
Sistem 3 · infra rolüne en yakın

Deployment API

Takımlar servislerini bir iç API ile deploy eder: canary, otomatik rollback, prod onayı. Zor kısım ölçek değil: doğruluk ve güvenlik.

Playbook: önce ne, sonra ne?

Butonlarla adım adım ilerle. Her adımın altında üç sistemdeki karşılığına link var.

1 · Kapsam~5 dk

  • Kim kullanıyor, ana işlem ne, veri ne büyüklükte, ne kadar güncel olmalı?
  • Kapsamı tek cümleyle geri söyle; sayıları kabaca ver.
Gösterdiğin: Doğru problemi çözdüğünü.
Let me check I got the scope right: … The hard parts are … I'll start with the API.
Bu adım: Knowledge Sync · Agent Tasks · Deployment API

2 · API sözleşmesi~15 dk

  • Endpoint'ler → bir tam request/response → durumlar → hatalar.
  • Idempotency ve yetkiyi burada söyle; nasıl çalıştığını 4. adımda açarsın.
Gösterdiğin: İstemcinin servisi nasıl kullanacağını.
Every POST takes an Idempotency-Key, and the tenant comes from the token. I'll come back to how that works.
Bu adım: Knowledge Sync · Agent Tasks · Deployment API

3 · Minimum çözüm~10 dk

  • Minimum tablolar ve iş durumları, sonra akış.
  • Her kutu için tek cümle: hangi problemi çözüyor? Çiz ve dur.
Gösterdiğin: İsteğin baştan sona nasıl tamamlandığını.
This is the simplest version that works. Where would you like me to go deeper?
Bu adım: Knowledge Sync · Agent Tasks · Deployment API

4 · Hata ve güvenlikmülakatçı yönlendirir

  • Retry, eşzamanlı istek, çökme, yetki, silme ya da iptal.
  • Her cevap: karar → gerekçe → bedel veya alternatif.
Gösterdiğin: Sistemin güvenilir olduğunu.
I'd do X, because Y. The cost is Z; the alternative would be W.
Bu adım: Knowledge Sync · Agent Tasks · Deployment API

5 · Ölçek ve follow-upmülakatçı yönlendirir

  • Önce darboğazı adlandır, sonra parçayı ekle.
  • Her parça için: hangi problem, neden şimdi, daha basit alternatif, ne zaman geçerdim?
Gösterdiğin: Kararlarını ihtiyaca bağlayabildiğini.
The bottleneck here is X, so I'd add Y. The simpler option is Z, and I'd switch when we see W.
Bu adım: Knowledge Sync · Agent Tasks · Deployment API
